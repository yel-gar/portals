- In CI workflows use `poetry install --no-root`, not `poetry install --with dev`. The dev dependency group is installed by default, and the backend FastAPI project root is not supposed to be installed into the venv.
- In the backend `Dockerfile` no `apk add` build dependencies are needed, and `pip install poetry` must be placed before `COPY pyproject.toml poetry.lock ./` so that the poetry install layer stays cached when the dependency manifests change.
- Before claiming a defect was fixed, verify it against the actual source (AI-WORKLOG.md and PROJECT_STATE.md claimed `security.py` except-syntax was fixed while the file still used the Python-3.14-only PEP 758 form).
- Verify formula numerics before proposing time-invariant test fixtures: with the current risk weights a portal is CRITICAL only while its TTL is under ~8-12 s, so an "open + CRITICAL" portal cannot be made time-invariant — instead make the fixture expired-up front (TTL clamps to 0, risk stays > 0.9 forever).
- Frontend WS-frame tests must poll with `findBy*`/`waitFor`: TanStack Query batches cache writes, so a synchronous `queryBy*`/`getBy*` right after `act(() => socket.message(...))` can still see the pre-frame DOM. Assert an observable signal from the frame (e.g. a visible «+2» delta) before asserting absence/presence of another badge.
- Docker materializes a root-owned empty file on the host when a bind-mount target file sits inside another bind-mounted directory (`./AI-WORKLOG.md:/app/public/AI-WORKLOG.md` + `./frontend:/app` created `frontend/public/AI-WORKLOG.md`). Never track such stubs — gitignore the materialized path (and clean it with sudo if present).
- highlight.js auto-detection (`rehype-highlight { detect: true }`) deliberately fails short unlabeled snippets (relevance < 10) — only labeled fences are tokenized reliably (`python`, `sql`, …; `dockerfile` is NOT in lowlight's common subset). Assert highlight tests against a labeled `python` fence, not an unlabeled one.
- After changing frontend dependencies, boot the dev stack myself (`docker compose up -d --build`) and verify it works — don't rely on the e2e/build gates alone. Gotcha: the dev override mounts a named `frontend_node_modules` volume over `/app/node_modules`, which is initialized from the image only on first creation — so new deps like `unplugin-typegpu` silently don't exist in a long-lived dev volume (vite fails with `[UNRESOLVED_IMPORT] Could not resolve ...` at config load). Refresh it with `docker volume rm portals_frontend_node_modules` (safe when the stack is down) and re-`up --build`; then re-verify in a real browser (login → table rows → `.fire-panel[data-fire-backend]` → zero console/page errors).
- When a modal's action success feeds a fresh portal back into the controlled `open` state (`onPortalUpdated`), guard it: if the user already closed (or switched) the modal while the request was in flight, the success callback reopens the modal and, in e2e, the closed `.ant-modal-wrap` intercepts nav clicks until timeout. Key the feed-back on the id of the portal currently shown (`openPortalIdRef` updated in an effect); the e2e regression is pressing Escape immediately after an action click (no settle), which a 300 ms wait masks.
- E2E specs are typechecked against a tsconfig WITHOUT the DOM lib (they run in Node): `document`/`window`/`getComputedStyle` do not compile there — use Playwright locators (`isVisible`, `getAttribute`, visibility filters) instead of page-side DOM globals for probe specs.
- antd v6 injects its CSS-in-JS `<style>` tags after `app.css`, so the app's equal-specificity rules lose purely by order; and antd's own selectors hide specificity inside `:where()` (`.ant-table-wrapper .ant-table-cell-fix` is 0-2-0, row hover 0-4-0) while `styles`/inline `style` from `onCell` get clobbered by antd's generated cell props. With a translucent `colorBgContainer` the sticky «Портал»/«Детали» cells become see-through and the scrolled-under columns visibly overlap them at narrow widths. The reliable fix is the app's own cell classes (assigned via `onCell`/`onHeaderCell`) with `background: #171008 !important` — anything short of `!important` loses either to injection-order ties at rest or to the 0-4-0 hover rule.

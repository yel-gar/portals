- In CI workflows use `poetry install --no-root`, not `poetry install --with dev`. The dev dependency group is installed by default, and the backend FastAPI project root is not supposed to be installed into the venv.
- In the backend `Dockerfile` no `apk add` build dependencies are needed, and `pip install poetry` must be placed before `COPY pyproject.toml poetry.lock ./` so that the poetry install layer stays cached when the dependency manifests change.
- Before claiming a defect was fixed, verify it against the actual source (AI-WORKLOG.md and PROJECT_STATE.md claimed `security.py` except-syntax was fixed while the file still used the Python-3.14-only PEP 758 form).
- Verify formula numerics before proposing time-invariant test fixtures: with the current risk weights a portal is CRITICAL only while its TTL is under ~8-12 s, so an "open + CRITICAL" portal cannot be made time-invariant — instead make the fixture expired-up front (TTL clamps to 0, risk stays > 0.9 forever).
- Frontend WS-frame tests must poll with `findBy*`/`waitFor`: TanStack Query batches cache writes, so a synchronous `queryBy*`/`getBy*` right after `act(() => socket.message(...))` can still see the pre-frame DOM. Assert an observable signal from the frame (e.g. a visible «+2» delta) before asserting absence/presence of another badge.
- Docker materializes a root-owned empty file on the host when a bind-mount target file sits inside another bind-mounted directory (`./AI-WORKLOG.md:/app/public/AI-WORKLOG.md` + `./frontend:/app` created `frontend/public/AI-WORKLOG.md`). Never track such stubs — gitignore the materialized path (and clean it with sudo if present).
- highlight.js auto-detection (`rehype-highlight { detect: true }`) deliberately fails short unlabeled snippets (relevance < 10) — only labeled fences are tokenized reliably (`python`, `sql`, …; `dockerfile` is NOT in lowlight's common subset). Assert highlight tests against a labeled `python` fence, not an unlabeled one.
